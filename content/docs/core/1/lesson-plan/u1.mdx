## MODULE 1: Overview of Python (Features & Paradigm Comparisons)

### **Lesson Objective**
Analyze Python's core characteristics (high-level abstraction, dynamic typing, automatic memory management, and platform independence) and contrast its multi-paradigm architecture (procedural, object-oriented, and functional) with C’s procedural framework and Java's pure class-based model.

### **Core Concepts**
* **High-Level Abstraction:** High-level languages use English-like structures to maximize algorithmic focus and minimize boilerplate instructions.
* **Dynamic Typing:** Variable declarations are absent in Python. The runtime interpreter associates types with value objects on the heap dynamically rather than the variable name tags themselves at compile time.
* **Platform Independence & Portability:** Python source compiles to intermediate, host-agnostic bytecode, which is executed across hardware systems via platform-specific interpreters.
* **Multi-Paradigm Execution:** Python acts as a hybrid engine, allowing developers to write procedural script-level code, object-oriented software using classes, or functional modules with lambda pipelines.

## MODULE 2: Setting Up the Python Environment (Python Installation, IDEs)

### **Lesson Objective**
Install Python, configure system variables, verify terminal environments, and execute Python code using both the Interactive Shell (REPL) for fast testing and Script Mode for persistent program storage.

### **Core Concepts**
* **Verifying System PATH:** Setting environment variables ensures the CPython interpreter and package managers (like `pip`) are accessible globally from any shell terminal.
* **Interactive Mode (REPL):** Running statements immediately under the triple greater-than (`>>>`) primary prompt. The interpreter dynamically evaluates the expression and auto-prints any return values without requiring explicit print statements.
* **Script Mode:** Compiling and executing complete code sequences stored as physical `.py` files. In this mode, evaluated expressions do not print output to the console unless passed directly to output statements [B1 Page 34].

## MODULE 3: Python Syntax: Variables and the Tag Reference Model

### **Lesson Objective**
Contrast C's physical "storage box" variable allocation model with Python's heap-allocated "tag reference" (sticky-note) model, explaining object aliasing, dynamic reference tracking, and garbage collection.

### **Core Concepts**
* **The Box Model (C):** A variable represents a static physical memory slot on the system stack that directly contains a binary value. Writing a new value overwrites the bits at that specific address.
* **The Tag Model (Python):** Python values exist as individual objects on the heap. Assigning a variable does not reserve memory for a value; instead, it binds an identifier tag to an existing heap object.
* **CPython Pointer Overhead:** A C integer takes 4 bytes. A Python integer takes 28 bytes because CPython represents it as a complex C structure (`struct _longobject`) containing reference counting metrics (`ob_refcnt`), type descriptors (`ob_type`), and size headers alongside the raw value.
* **Reference-Counting Garbage Collection:** Every object tracks how many variable tags are bound to it. When an object's reference count drops to 0, the PVM's memory manager sweeps it from the heap to free memory.

## MODULE 4: Built-in Data Types & Sequence Operations

### **Lesson Objective**
Categorize Python's built-in data types, perform sequence manipulations using slicing with strides, and execute explicit type conversions (coercion) safely.

### **Core Concepts**
* **None Type:** Represents a single singleton object (`None`) indicating the absolute absence of a value.
* **Numeric Types:** Distinguish between fixed-precision standard integers, double-precision floats, and complex numbers (`real + imag j`).
* **Sequence Types:** Ordered collection types including strings (immutable), tuples (immutable), lists (mutable), and range sequences.
* **Step-Stride Slicing:** Extracting subsequences with the syntax `sequence[start:stop:step]`. Negative step strides reverse the order.
* **Explicit Coercion:** Converting variable types explicitly using built-in constructors: `int()`, `float()`, `str()`, and `complex()`.

## MODULE 5: Operators, Precedence, and Expressions

### **Lesson Objective**
Construct and evaluate expressions using Python’s operators, adhering strictly to interpreter precedence, associativity hierarchies, and short-circuit evaluation rules.

### **Core Concepts**
* **Division Variations:** Contrast standard float division (`/`) with integer floor division (`//`) and remainder modulo operations (`%`).
* **Logical Short-Circuiting:** Logical `and` and `or` operate as short-circuit expressions, evaluating from left to right and returning the actual evaluated operand object rather than a simple boolean flag.
* **Value Equality vs. Identity:** Structural value comparison (`==`) checks whether objects contain the same data. Reference identity comparison (`is`) checks whether two tags point to the exact same heap memory block.
* **Associativity and Precedence:** Operational priority runs from parenthetical bounds, to exponential powers (`**`), to multiplication/division groups, down to additive groups and logical structures.

## MODULE 6: Under the Hood — The Python Compilation & Execution Pipeline

### **Lesson Objective**
Trace Python's hybrid compilation and execution pipeline under standard CPython, explaining the role of bytecode cached within `__pycache__` directories and disassembling stack operations inside the PVM.

### **Core Concepts**
* **The Translation Boundary:** Source code (`.py`) is compiled into host-agnostic, byte-sized instruction sets (bytecode cached as `.pyc` files under `__pycache__`).
* **The Virtual Machine:** The PVM hosts an internal interpreter that translates bytecode instructions line-by-line into system-native machine assembly instructions dynamically at runtime.
* **Stack-Based Execution:** Unlike register-based CPUs (and register-targeted C compilation), the PVM operates as a virtual stack-based evaluation machine.
* **The `dis` Module:** The standard disassembler library exposes the raw stack operations used by the PVM.

## MODULE 7: Troubleshooting, Error Classifications, and Debugging

### **Lesson Objective**
Classify script failures systematically into compile-time (syntax), runtime (exceptions), and logical (semantic) errors, and read system traceback diagnostics to identify execution context scopes.

### **Core Concepts**
* **Syntax Errors:** Typos caught by the compiler before bytecode generation begins. If a syntax error is present, no instructions are executed.
* **Runtime Exceptions:** Logical operations that fail during program execution (e.g., `TypeError`, `ZeroDivisionError`, `NameError`), terminating the execution stack immediately unless managed by exception blocks.
* **Semantic (Logical) Errors:** Algorithmic failures. The program executes perfectly without crashing, but yields incorrect mathematical or analytical results.
* **Tracebacks:** Interactive diagnostic summaries displaying the exact nested call stack frames that led to a runtime exception.
