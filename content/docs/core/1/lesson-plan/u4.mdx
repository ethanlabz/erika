## MODULE 1: Filesystem Basics, Path Engineering, and Directory Operations

### **Lesson Objective**
Students will be able to construct cross-platform path references, navigate directory structures programmatically, and perform robust folder manipulation, verification, and directory-tree walks using the `os` and `shutil` modules [B5 Ch. 17, B2 Ch. 8, 9].

### **Core Concepts**
* **Path Representation Differences:** Windows backslashes (`\\` which must be escaped) vs. POSIX forward slashes (`/`). Using `os.path.join()` to dynamically build platform-independent path strings [B2 Page 173–174].
* **Execution Context:** The Current Working Directory (CWD). Retrieving the CWD with `os.getcwd()` and changing the execution directory with `os.chdir()` [B2 Page 175].
* **Absolute vs. Relative Paths:** Distinguish absolute root paths from relative paths mapped from the CWD. Understand special directory tokens: dot (`.`) for the current folder and double-dot (`..`) for the parent folder [B2 Page 175–176].
* **Directory Verification & Metadata:**
  * `os.makedirs(path, exist_ok=True)`: Recursive directory creation, building all nested intermediate subdirectories [B2 Page 176].
  * Checking validity: `os.path.exists()`, `os.path.isfile()`, and `os.path.isdir()` [B2 Page 180].
  * Gathering metrics: `os.path.getsize()` to retrieve file size in bytes, and `os.listdir()` to return flat arrays of directory filenames [B2 Page 179].
* **Directory Traversal:** Leveraging `os.walk(path)` to perform recursive top-down or bottom-up directory traversals. Understand that on each iteration, it yields a 3-tuple containing: the current directory path string, a list of subdirectories, and a list of filenames [B5 Page 473, B2 Page 202].
* **Shell Utilities (shutil):** High-level operations for copying files (`shutil.copy()`), copying entire directory trees (`shutil.copytree()`), moving/renaming directory elements (`shutil.move()`), and deleting non-empty directories recursively (`shutil.rmtree()`) [B2 Page 198, 200].

## MODULE 2: Plaintext File Operations, Stream Lifecycles, and Stream Read/Write Mechanics

### **Lesson Objective**
Students will master the complete lifecycle of a file stream (Open $\rightarrow$ Process $\rightarrow$ Close), distinguish between the 12 explicit text and binary access modes, and evaluate the memory implications of various stream-reading strategies [B1 Sec 5.9, B5 Ch. 17, B2 Ch. 8].

### **Core Concepts**
* **Association Boundary:** The `open(file, mode)` constructor associates a physical file stored in secondary storage with a virtual file stream object in volatile heap memory [B1 Page 159, B5 Page 443].
* **Text vs. Binary Streams:** Text files represent data as individual character blocks (applying encoding transformations like UTF-8), while binary files handle raw, unmodified byte-streams (e.g., images, compressed packages) [B5 Page 442, B2 Page 180–181].
* **Matrix of File Opening Access Modes:**
  * `'r'` / `'rb'`: Read-only. Stream cursor positioned at the absolute start (0). Raises FileNotFoundError if the file is absent [B5 Page 443].
  * `'w'` / `'wb'`: Write-only. Erases existing contents (truncates) or creates a new file if absent [B5 Page 443].
  * `'a'` / `'ab'`: Append-only. Cursor placed at the absolute end. New data is appended; existing data is preserved [B5 Page 443].
  * `'+'` Modifier (`'r+'`, `'w+'`, `'a+'`): Enables dual read and write pipelines. Modifies behavior based on primary mode limits [B5 Page 443–444].
* **Stream Reading API Evaluations:**
  * `.read(n)`: Reads `n` bytes/characters as a single string. If `n` is omitted, reads the entire remaining file. High memory overhead for large files [B1 Page 161, B5 Page 446].
  * `.readline()`: Reads the stream up to and including the next newline (`\n`) character. Returns an empty string `""` at EOF [B1 Page 161].
  * `.readlines()`: Loads the entire remaining stream into a list of strings where each element is a line. High memory consumption [B1 Page 161].
* **High-Performance Lazy Line Iteration:** Iterating directly over the file object using a `for line in file_object` loop. This utilizes a lazy buffer generator, loading only one line into memory at a time [B1 Page 162].
* **Stream Writing API:**
  * `.write(string)`: Writes a character string to the stream. Does not append newlines automatically [B1 Page 162].
  * `.writelines(list_of_strings)`: Writes a sequence of strings to the stream sequentially [B1 Page 162].
* **The Closing Policy:** Failing to call `.close()` locks files in the OS file descriptor table, prevents buffered data from flushing to disk, and can result in memory leaks or corrupted writes [B1 Page 160, B5 Page 444, B2 Page 181].

## MODULE 3: Context Managers and Exception-Safe File I/O

### **Lesson Objective**
Students will design robust, exception-safe file input/output pipelines utilizing Python's `with` context manager statement and structure layered `try-except-else-finally` exception-handling blocks [B5 Ch. 16, 17, PCC Ch. 10].

### **Core Concepts**
* **The Context Manager Protocol:** The `with` statement guarantees resource cleanup. Under the hood, the block invokes the context manager's `__enter__()` method upon entry, and guarantees the execution of `__exit__()` upon exit—even if unhandled runtime exceptions are raised inside the block [B5 Page 452].
* **Automatic Stream Closure:** In a `with open(...) as file` block, the file object's `close()` method is automatically called immediately upon exiting the scope of the block [B5 Page 452].
* **Robust Exception Safety:** File operations are highly prone to operating system errors. Programs must anticipate and handle:
  * `FileNotFoundError`: Trying to read a file that does not exist at the specified path [PCC Page 203].
  * `PermissionError`: Trying to access or write to a restricted system file or folder without sufficient user privilege.
  * `UnsupportedOperation`: Attempting write actions on a stream opened in read-only mode [B5 Page 422].
* **Structuring the I/O Block:**
  * `try`: Encloses dangerous operations (file open, stream read, stream write) [B5 Page 428, PCC Page 200].
  * `except`: Captures specific system exceptions and prevents program crash [B5 Page 428, PCC Page 201].
  * `else`: Executes blocks only if the `try` block ran without raising any exceptions [B5 Page 428, PCC Page 202].
  * `finally`: Guarantees cleanup execution (e.g., forcing a stream closure if not using a context manager), regardless of execution success or failure [B5 Page 428].

## MODULE 4: File Pointer Navigation and Random Access

### **Lesson Objective**
Students will manage stream cursors within binary and text files using byte positioning, tracking offset positions with `.tell()`, and applying random-access navigation via `.seek()` [B5 Ch. 17].

### **Core Concepts**
* **The Stream Pointer:** Stream operations are sequential. As reading or writing occurs, the file pointer shifts by the byte-length of the data processed [B5 Page 456].
* **Tracking Position (.tell()):** Returns an integer representing the current byte offset of the file pointer relative to the absolute start of the file [B5 Page 456].
* **Stream Navigation (.seek(offset, fromwhere)):** Moves the stream cursor to a custom position:
  * `offset`: The signed integer byte distance to move the pointer [B5 Page 456].
  * `fromwhere`: Specifies the reference point for the offset:
    * `0` (Default): Beginning of the file. The cursor is placed at `0 + offset`. Offset must be positive [B5 Page 456].
    * `1`: Current cursor position. Cursor is placed at `current + offset`. Only allowed in binary mode [B5 Page 456].
    * `2`: End of the file. Cursor is placed at `EOF + offset`. Commonly used with negative offsets to read backwards. Only allowed in binary mode [B5 Page 456–457].
* **Text Mode Restriction:** In standard Python 3 text streams, `.seek()` is restricted to absolute seek operations from the start of the file (`fromwhere=0`), or seeks targeting the exact value returned by a previous `.tell()` call. Seeking with relative positions (`fromwhere=1` or `2`) raises `io.UnsupportedOperation` [B5 Page 457].

## MODULE 5: Structured Plaintext Persistence: Parsing and Writing CSV Files

### **Lesson Objective**
Students will read, parse, and write structured matrix datasets stored as Comma-Separated Values (CSV) using the standard `csv` library, ensuring safety against Windows newline insertion bugs and handling escape sequences [B2 Ch. 14, PCC Ch. 16].

### **Core Concepts**
* **The CSV Format Structure:** CSV is a simplified spreadsheet stored as plaintext. Rows are separated by carriage returns/newlines, and individual cells are delimited by commas [B2 Page 319, PCC Page 649].
* **Escape Sequences & Parsing Hazards:** Relying on basic string splitting (`line.split(',')`) is highly fragile. If a cell contains a literal comma (e.g., `"New York, USA"`), standard splitting corrupts the database. The `csv` module natively parses RFC 4180 escape standards [B2 Page 321–322].
* **The csv.reader Stream:** Wraps a text file object, parsing each line dynamically and yielding row records as lists of strings in a loop [B2 Page 321–322, PCC Page 650].
* **The csv.writer Stream:** Writes records to a CSV file. The `.writerow(list)` method takes a list of data cells, formats them dynamically with quotes when needed, and writes them to the file [B2 Page 322–323].
* **Windows Newline Padding Bug:** On Windows platforms, omitting `newline=''` when invoking `open()` for writing causes Excel-compatible CSV writers to output double-spaced blank rows. Always open CSV streams with `newline=''` [B2 Page 323, 325].
* **Custom Delimiters:** Standardizing tab-separated spreadsheets (TSV) by specifying custom delimiters (`delimiter='\t'`) and customizing line terminators (`lineterminator='\n'`) inside the writer constructor [B2 Page 323].

## MODULE 6: Structured Object Serialization: JSON and Binary Pickling

### **Lesson Objective**
Students will serialize and deserialize Python heap objects, comparing standard-compatible, human-readable JSON streams with Python-specific, high-performance binary pickle serialization [B5 Ch. 17, B2 Ch. 14, PCC Ch. 10].

### **Core Concepts**
* **Object Serialization (Marshalling):** The process of translating a live heap-allocated Python object structure into an equivalent sequential byte-string or character stream suitable for file-storage or network transmission [B5 Page 452, PCC Page 637].
* **JSON (JavaScript Object Notation) Pipelines:**
  * A universally compatible, lightweight plaintext format [B2 Page 327, PCC Page 638].
  * **Data Type Boundaries:** JSON can store only basic primitive types: strings, integers, floats, booleans, lists, dictionaries, and None [B2 Page 328]. Python-specific classes, datetime objects, and byte streams are unsupported.
  * **Memory-to-String APIs:** `json.dumps(obj)` converts a Python object to a JSON formatted string; `json.loads(str)` parses a JSON string into a Python object structure [B2 Page 328–329].
  * **Disk-to-File APIs:** `json.dump(obj, file_obj)` writes object directly to a JSON file; `json.load(file_obj)` parses a JSON file into a Python object directly [PCC Page 209].
* **Pickling (Python Serialization):**
  * A Python-specific binary serialization protocol [B5 Page 452].
  * Can serialize almost any complex, nested custom class instance or custom data structure [B5 Page 453].
  * **Methods:** Using the `pickle` module: `pickle.dump(obj, file_obj)` writes object as byte stream; `pickle.load(file_obj)` rebuilds object [B5 Page 454].
  * **Critical Security Policy:** Never unpickle data from untrusted sources. Rebuilding an object from an unverified pickled file can execute arbitrary malicious code on the host system.

## MODULE 8: Custom Module Design, Namespace Engineering, and Python execution Boundaries

### **Lesson Objective**
Students will engineer reusable, self-contained custom libraries, structure modular packages, manage imports cleanly to avoid namespace pollution, and construct execution bounds using the special variable `__name__` [B5 Ch. 9, B1 Sec 5.11, B3 Sec 5.11].

### **Core Concepts**
* **The Modularization Philosophy:** Dividing large software files into small, easily maintainable, and reusable files (modules) containing related functions, classes, and variables [B5 Page 277].
* **Syntax of Importing namespaces:**
  * `import custom_module`: Accesses resources through explicit dot notation (e.g., `custom_module.calculate()`). Best practice to protect namespace integrity and prevent naming collisions [B5 Page 218].
  * `from custom_module import calculate`: Binds the specific name directly into the caller namespace [B5 Page 218].
  * `from custom_module import *`: Pollutes the local namespace by importing all identifiers. Highly dangerous as it silently overrides local definitions without raising warnings [B5 Page 218].
  * `as aliases`: Creating local aliases for imported namespaces to prevent collisions (`import pandas as pd`) [B5 Page 219].
* **The Special Variable `__name__`:** Dynamically updated by the PVM [B5 Page 279, B1 Page 215].
  * When a script is executed directly (e.g., `python script.py`), Python assigns the string `'__main__'` to `__name__` [B5 Page 279, B1 Page 215].
  * When a script is imported as a module into another script (e.g., `import script`), Python assigns the actual filename of the module (`'script'`) to `__name__` [B5 Page 279, B1 Page 215].
* **The Execution Shield (`if __name__ == '__main__':`):** Placing script execution routines inside this block allows modules to act as dual-mode entities: they execute standalone scripts when run directly, but act as silent, clean libraries when imported elsewhere without executing their script procedures [B5 Page 279, B1 Page 215].
