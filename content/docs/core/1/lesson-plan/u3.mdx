## MODULE 1: String Representations, Indexing, and Slicing with Stride

### **Lesson Objective**
Understand Python's string storage models (heap-allocated immutable character sequences), master positive/negative indexing boundaries, and apply step-stride slicing arithmetic (including string reversals) [B5 Page 207, B1 Page 129].

### **Core Concepts**
* **String Immutability:** Explain that strings are immutable heap objects. Any modification creates a new string object rather than modifying the existing character array in-place, which optimizes hashing stability and enables string interning [B5 Page 208].
* **Memory Representation:** Contrast C’s null-terminated character array (`char[]` utilizing `\0`) with Python’s high-level `str` object, which caches length, hash values, and encodes characters using Unicode standard [B5 Page 403].
* **Index Boundaries:** Trace indexing from `0` to `len(s)-1` (left-to-right) and negative indexing from `-1` to `-len(s)` (right-to-left) [B1 Page 131].
* **Step-Stride Slicing:** Understand the slice syntax `s[start:stop:step]`. Explain that a negative step moves backward through the string and how `s[::-1]` performs a full string reversal [B5 Page 210, B1 Page 132].

## MODULE 3: Lists: Creation, Mutability, and Memory Architecture

### **Lesson Objective**
Explain Python's contiguous heap-pointer list representation, analyze mutability behavior (append, insert, and delete), and contrast memory aliasing with cloning [B5 Page 283, B1 Page 366].

### **Core Concepts**
* **List Memory Representation:** Contrast C’s contiguous, homogeneous arrays with Python's contiguous arrays of object references. Python lists store pointers pointing to heterogeneous heap structures, explaining why lists can hold mixed datatypes at a slight pointer dereferencing cost [PDSH Page 35, B5 Page 284].
* **The Mutability API:** Trace how elements are appended in $O(1)$ amortized time, inserted in $O(N)$ linear time, and removed via `del`, `.pop()`, or `.remove()` [B5 Page 288, 293–294, B2 Page 84].
* **Aliasing vs. Cloning:** Understand that `list2 = list1` merely copies the heap pointer address (aliasing), while slicing `list2 = list1[:]` or using `list1.copy()` creates a shallow copy (cloning) [B5 Page 291].
* **Sorting:** Use `.sort()` to modify the list in-place, or `sorted()` to return a new sorted list, optionally utilizing lambda custom key extractors [B5 Page 296, B1 Page 378].

## MODULE 5: Tuples: Creation, Immutability, and Unpacking

### **Lesson Objective**
Contrast tuples with lists, understand syntax requirements for singletons, evaluate performance advantages, and utilize sequence unpacking [B5 Page 307, B1 Page 387].

### **Core Concepts**
* **Tuple Definition & Immutability:** Explain that tuples are immutable sequence structures. Since they cannot change shape or size, the interpreter optimizes their allocation speed and memory footprints [B5 Page 307].
* **Singleton Syntax Boundary:** Highlight that single-element tuples require a mandatory trailing comma (e.g., `(42,)` vs. parenthesized expression `(42)`), which distinguishes them from parenthesized integers in math expressions [B5 Page 307, B2 Page 96].
* **Tuple Unpacking:** Unpack multiple sequence elements into distinct variables in a single assignment (e.g., `x, y = coord`), enabling elegant swappings and multiple-value function returns [B1 Page 387, B5 Page 309].
* **Memory Overhead Advantages:** Since tuples are read-only, CPython executes them in a static, pre-allocated memory chunk, making them faster to process than dynamically resized lists [B5 Page 319].

## MODULE 6: Dictionaries: Hash Tables, Keys, and Comprehensions

### **Lesson Objective**
Explain Python's dictionary mapping architecture, enforce strict key mutability constraints, apply safe retrieval methods, and construct dictionary comprehensions [B5 Page 321, B1 Page 401].

### **Core Concepts**
* **Hash Tables & Mappings:** Understand that dictionaries are mappings implementing highly efficient, constant-time $O(1)$ key search retrievals using a hash table structure under the hood [B1 Page 401, B5 Page 321].
* **Strict Key Constraints:** Keys must be unique and belong strictly to immutable datatypes (such as strings, integers, or tuples), which ensures their generated hash remains stable over their lifetime [B5 Page 323]. Mutable types (like lists) cannot be hashed and will raise a `TypeError` if used as keys [B5 Page 323, B2 Page 105].
* **Safe API Extraction:** Use `.get(key, default)` to query dictionary items safely. This prevents run-time `KeyError` crashes when keys are missing [B5 Page 330, B2 Page 109].
* **Dictionary Comprehensions:** Construct populated dictionaries dynamically using `{key_expr: value_expr for item in sequence}` [B5 Page 307, B2 Page 120].

## MODULE 7: Sets & the Standard Collections Module

### **Lesson Objective**
Apply unique, unordered set data structures, execute core set operations (union, intersection, difference, and symmetric difference), and leverage standard library structures like OrderedDict and Counter [B5 Page 61, 335, B3 Page 360, B1 Page 414].

### **Core Concepts**
* **Unordered Set Properties:** Sets are unordered collections of unique elements. They are useful for removing duplicates and executing membership checks in constant time $O(1)$ [B5 Page 61, B1 Page 414].
* **Mathematical Operations:** Implement set operations using built-in operators: union (`|`), intersection (`&`), difference (`-`), and symmetric difference (`^`) [B5 Page 61, B3 Page 360].
* **collections.OrderedDict:** Traditional dictionaries did not preserve key insertion order. Leverage `OrderedDict` to combine the lookup speed of a dictionary with the sequence order of a list [B5 Page 335, PCC Page 215].
* **collections.Counter:** A specialized dictionary subclass designed specifically for tallying elements quickly and cleanly [B3 Page 365, PCC Page 215].
