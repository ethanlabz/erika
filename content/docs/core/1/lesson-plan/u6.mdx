## MODULE 1: High-Performance Numerical Computing with NumPy (Vectorization & Broadcasting)

### **Lesson Objective**
Students will be able to analyze CPython's loop overhead bottleneck, explain the contiguous C-array memory layout of NumPy ndarrays compared to Python's pointer-based lists, apply vectorized universal functions (Ufuncs) to eliminate loops, and implement broadcasting rules to evaluate multi-dimensional calculations efficiently [PDSH Ch. 6, 8, B5 Ch. 7].

### **Core Concepts**
* **The Bottleneck of Python Loops:** Traced to CPython's dynamic type-checking overhead and reference-counting redirection. For every loop iteration, CPython must inspect the object's header struct (`ob_type`) to determine its datatype and resolve method dispatches, adding massive processing latency [PDSH Page 51, 52].
* **Contiguous C-Array Memory Layout:** NumPy ndarrays are homogeneous contiguous blocks of raw bytes pointing directly to fixed-size datatypes (e.g., float64, int32), matching C-style arrays. This avoids the 28-byte overhead of standard Python integers [PDSH Page 35, 36, B5 Page 141].
* **Universal Functions (Ufuncs):** Vectorized mathematical wrappers implemented in compiled C that perform element-wise operations on arrays, bypassing the PVM loop evaluation cycle completely [PDSH Page 52, 53].
* **Broadcasting Rules:** Rules for performing operations on arrays of different shapes:
  * If the arrays differ in their number of dimensions, the shape of the array with fewer dimensions is padded with ones on its leading (left) side [PDSH Page 67].
  * If the shape of the two arrays does not match in a given dimension, the array with a shape equal to 1 in that dimension is stretched to match the other shape [PDSH Page 67].
  * If in any dimension the sizes disagree and neither is equal to 1, a broadcasting error is raised [PDSH Page 67].

## MODULE 2: Structured Data Manipulation with Pandas (Series & DataFrames)

### **Lesson Objective**
Students will be able to construct Pandas Series and DataFrames, explain index alignment mechanics, load unstructured flat CSV data into structured memory spaces, and execute relational database operations (boolean indexing, filtering, selecting, and grouped aggregations) on structured data tables [PDSH Part III, B5 Ch. 25].

### **Core Concepts**
* **The Series Object:** A one-dimensional homogeneous array of indexed data, combining the performance properties of a NumPy array with the explicit label-index lookup capabilities of a Python dictionary [PDSH Page 101, 102].
* **The DataFrame Object:** A two-dimensional, size-mutable, heterogeneous tabular data structure containing aligned columns of Labeled Series objects sharing a unified index [PDSH Page 104, 105].
* **Index Alignment:** Alignment of data based on row labels during operations. Missing keys on either side are automatically padded with float64 NaN values [PDSH Page 116].
* **Boolean Masking & Relational Queries:** Extracting subsets of a DataFrame based on boolean evaluations matching structural criteria, equivalent to SQL WHERE queries [PDSH Page 72, 73, 137].
* **Split-Apply-Combine:** The grouping operation workflow:
  * Split the DataFrame into subsets based on key values [PDSH Page 162].
  * Apply an aggregation function (e.g., mean, sum, count) to each sub-group [PDSH Page 162].
  * Combine the output vectors into a unified resulting DataFrame [PDSH Page 162].

  * **Histograms:** Best for displaying the probability distribution of a single continuous variable [PDSH Page 211].
* **Seaborn Statistical Aesthetics:** Seaborn is built on top of Matplotlib, integrating statistical analysis directly into the visualization layout. It provides high-level APIs to render complex plots like factor counts, violin plots, and linear regression fits with beautiful default styles and color palettes [PDSH Page 340].

## MODULE 4: Web Scraping and HTML Harvesting (Requests & BeautifulSoup)

### **Lesson Objective**
Students will be able to outline the HTTP request-response pipeline, extract raw HTML trees using the `requests` library, handle HTTP exceptions defensively, parse and navigate the tree using CSS selectors inside BeautifulSoup, and write streams to download media files in dynamic data chunks [B5 Ch. 23, B2 Ch. 11].

### **Core Concepts**
* **HTTP Request-Response Protocol:** Web scraping starts by mimicking a client browser requesting resources from a server. The client sends a Request containing Header metadata (like User-Agent signatures to bypass bot blockers). The server returns a Response containing an HTTP Status Code (e.g., 200 OK, 404 Not Found) and raw body content [B2 Page 237, 238].
* **Defensive Connection Handling:** Scraping scripts must check for failures. Calling `response.raise_for_status()` immediately throws a runtime exception if the server returned a 4xx or 500-range error, allowing safe terminations [B2 Page 238].
* **HTML DOM Trees:** Web pages are structured hierarchically as a Document Object Model (DOM). Beautiful Soup compiles raw HTML text strings into nested Python object trees that can be navigated programmatically [B2 Page 245].
* **CSS Selector Parsing:** Navigating the parsed tree efficiently using the `.select()` API. It matches tags, IDs (`#id`), classes (`.class`), and nested children paths (e.g., `div.content p a`) [B2 Page 246, 247].
* **Buffered Stream Downloads:** To download binary assets (like images or PDF reports) without overloading system RAM, the stream must be downloaded in small sequential chunks using `response.iter_content()` and written to binary file streams (`'wb'`) [B2 Page 239, 240].

## MODULE 5: Scripting for Automation and Filesystem Operations (os & shutil)

### **Lesson Objective**
Students will be able to construct cross-platform file paths, traverse directory hierarchies dynamically using `os.walk()`, and automate file categorization, backup copying, renaming, and Zip compression utilizing the `os` and `shutil` modules [B5 Ch. 17, B2 Ch. 9].

### **Core Concepts**
* **Path Separator Conflicts:** Systems use different path delimiters (backslash `\` on Windows, forward slash `/` on Unix-like environments). Writing hard-coded string paths like `"C:\docs\file.txt"` breaks portability. Using `os.path.join()` or the object-oriented `pathlib.Path` resolves local OS separators automatically [B2 Page 174, 175].
* **Relative vs. Absolute Traversal:** Absolute paths map the exact path from root directories, while relative paths map paths relative to the current working directory [B2 Page 175, 176].
* **Directory Walks:** Walking the directories recursively using `os.walk()`. It crawls a target path, returning a 3-tuple (current directory path, list of child directories, and list of file names) on every loop pass [B5 Page 473, B2 Page 202, 203].
* **File Operations Management:**
  * `shutil.copy(src, dst)`: Copies a single file [B2 Page 198].
  * `shutil.move(src, dst)`: Moves or renames files/directories across paths [B2 Page 199].
  * `shutil.rmtree(path)`: Recursively and permanently deletes directory trees [B2 Page 200].
* **Automated Zip Archives:** Packaging folders into compressed `.zip` files using `zipfile.ZipFile`, capturing and adding individual path structures [B2 Page 205, 206].

    import zipfile

    for i in range(3):
        with open(os.path.join(source_dir, f"report_{i}.txt"), 'w') as f:

        with open(os.path.join(source_dir, f"data_{i}.csv"), 'w') as f:
            f.write("id,value\n1,100")

    # 2. Automation: Categorize files dynamically by checking extensions
    print("Categorizing directory...")
    for folder_name, subfolders, filenames in os.walk(source_dir):
        for filename in filenames:
            ext = os.path.splitext(filename)[1].lower()
            if ext == '.txt':
                target_subfolder = os.path.join(source_dir, "Text_Reports")
            elif ext == '.csv':
                target_subfolder = os.path.join(source_dir, "CSV_Data")
            else:
                continue

            os.makedirs(target_subfolder, exist_ok=True)
            shutil.move(os.path.join(folder_name, filename), os.path.join(target_subfolder, filename))
            print(f"Moved {filename} to {os.path.basename(target_subfolder)}/")

    # 3. Create a compressed ZIP archive of the organized directories
    archive_path = "organized_archive.zip"
    print(f"\nCompressing directory tree into: {os.path.basename(archive_path)}")
    with zipfile.ZipFile(archive_path, 'w', zipfile.ZIP_DEFLATED) as zip_file:
        for folder_name, subfolders, filenames in os.walk(source_dir):
            for filename in filenames:
                absolute_path = os.path.join(folder_name, filename)
                # Maintain relative directory hierarchy inside archive
                relative_path = os.path.relpath(absolute_path, source_dir)
                zip_file.write(absolute_path, relative_path)

## MODULE 7: Production Code Quality and Style Formatting (PEP 8)

### **Lesson Objective**
Students will be able to memorize and implement Python standard formatting guidelines (PEP 8), apply strict naming hierarchies (snake_case vs. CamelCase), manage line length constraints and imports, construct informative docstrings, and write PEP 8 compliant source code [B5 Ch. 9, B3 Ch. 5, PCC Ch. 8].

### **Core Concepts**
* **PEP 8 (Style Guide for Python Code):** The official styling document detailing constraints to maximize code readability [B5 Page 206, B3 Page 206].
* **Indentation & Whitespace Standards:** Use exactly 4 spaces per indentation level instead of tabs [B5 Page 206]. Place single spaces around binary operators (e.g., `=`, `+`, `==`) but avoid trailing space padding [B5 Page 206].
* **Identifier Naming Hierarchies:**
  * **Functions & Variables:** Written in lowercase, with words separated by underscores (`snake_case`) [B5 Page 206].
  * **Classes:** Written using capital letters without separators (`CamelCase` / `CapWords`) [B5 Page 206].
  * **Constants:** Written in all uppercase, separated by underscores (`UPPER_SNAKE_CASE`) [B5 Page 206].
* **Blank Lines & Code Structure:** Surround top-level function and class definitions with exactly two blank lines [B5 Page 206]. Methods inside a class are separated by a single blank line.
* **Explicit Imports:** Avoid wildcard imports (`from module import *`) as they pollute namespaces and cause variable name collisions. Keep imports separate and group them alphabetically [B5 Page 218].
* **Informative Docstrings:** Every module, class, and function must include a triple-quoted string (`"""docstring"""`) on the first line explaining its input parameters, return values, and behavior [B5 Page 205, 206].
